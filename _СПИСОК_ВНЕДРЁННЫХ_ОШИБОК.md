# Список внедрённых ошибок

> **Важно:** этот файл предназначен для автора и преподавателя. Команде, которая выполняет тестирование методом «чёрного ящика», его передавать не следует до завершения тестирования.

В учебную версию **Digital Card Platform** специально внедрено 7 функциональных дефектов. Ожидаемое корректное поведение описано в `ТЗ_Digital_Card_Platform.md`.

## OWN-01 — Поиск стал чувствительным к регистру

**Связанное требование:** ФТ-8.  
**Файл:** `client/src/components/cards-list.tsx`

Поисковый запрос приводится к нижнему регистру, но значения карточки перед сравнением больше не приводятся к нижнему регистру.

**Как проявляется:** если в карточке указано `Анна Смирнова`, поиск по части значения с другим регистром может не найти карточку.

**Ожидаемое поведение:** поиск по ФИО, компании, должности и `slug` должен быть регистронезависимым.

---

## OWN-02 — Карточка из списка открывается по ID вместо slug

**Связанное требование:** ФТ-9.  
**Файл:** `client/src/components/cards-list.tsx`

Ссылка на публичную страницу сформирована как `/v/{id}` вместо `/v/{slug}`.

**Как проявляется:** пользователь нажимает на карточку в общем списке и попадает на маршрут, который не соответствует её публичному адресу. В типовом случае публичная страница не находится.

**Ожидаемое поведение:** переход должен выполняться по `/v/{slug}`.

---

## OWN-03 — В буфер обмена копируется повреждённая публичная ссылка

**Связанное требование:** ФТ-14.  
**Файл:** `client/src/components/copy-link-button.tsx`

К исходному публичному URL при копировании добавляется лишний сегмент `/broken-link`.

**Как проявляется:** интерфейс сообщает «Ссылка скопирована», однако вставленное из буфера значение отличается от отображаемого URL и ведёт по неправильному адресу.

**Ожидаемое поведение:** в буфер обмена должен попадать точный публичный URL текущей визитки.

---

## OWN-04 — Логика подтверждения удаления инвертирована

**Связанное требование:** ФТ-7.  
**Файл:** `client/src/components/delete-card-button.tsx`

После системного диалога подтверждения условие обработано наоборот.

**Как проявляется:**

- при нажатии **OK / Подтвердить** удаление не выполняется;
- при нажатии **Cancel / Отмена** код продолжает выполнение и удаляет визитку.

**Ожидаемое поведение:** подтверждение должно удалять визитку, отмена — оставлять данные без изменений.

---

## OWN-05 — Валидация slug ошибочно разрешает только цифры

**Связанное требование:** ФТ-3.  
**Файл:** `client/src/components/card-form.tsx`

Финальная пользовательская валидация проверяет `slug` регулярным выражением, разрешающим только группы цифр и дефисы.

**Как проявляется:** нормальный адрес вида `anna-smirnova` отклоняется сообщением о недопустимом формате, хотя такой адрес соответствует ТЗ и подсказке формы.

**Ожидаемое поведение:** должны приниматься латинские буквы нижнего регистра, цифры и дефисы при корректном расположении дефисов.

---

## OWN-06 — При удалении соцссылки остаётся выбранная строка, а остальные удаляются

**Связанное требование:** ФТ-5.  
**Файл:** `client/src/components/card-form.tsx`

В фильтрации массива социальных ссылок условие инвертировано: сохраняется только элемент с выбранным индексом.

**Как проявляется:** если добавить несколько социальных ссылок и нажать «Убрать» у одной из них, выбранная строка остаётся, а другие строки исчезают.

**Ожидаемое поведение:** должна удаляться только выбранная строка, остальные должны сохраняться.

---

## OWN-07 — Ссылка «Сайт» открывает email вместо веб-сайта

**Связанное требование:** ФТ-11.  
**Файл:** `client/src/components/public-card.tsx`

Для блока «Сайт» в `href` подставляется `mailto:` с email визитки вместо значения поля `website`.

**Как проявляется:** текст блока содержит сохранённый URL сайта, но клик запускает почтовую ссылку либо не приводит к нужному сайту.

**Ожидаемое поведение:** ссылка «Сайт» должна открывать URL из поля `website`.
